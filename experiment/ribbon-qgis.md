# QGIS: a conventional interface, plus an experimental ribbon

Stock QGIS exposes commands through hierarchical menus, movable toolbars, task panels, the Processing Toolbox, and the Ctrl+K Locator rather than an Office ribbon. [QGIS GUI][gui]
A real **Ribbon Toolbar** plugin exists in the official plugin repository: its latest listed release is experimental 0.5.0, and its authors describe it as a discussion-oriented, non-production-ready prototype. [Registry][registry] · [Release][release] · [Author’s explanation][experiment]
[INFERENCE] For RustGIS, the useful comparison is not “QGIS has adopted ribbons,” but how a ribbon can selectively promote existing commands while preserving searchable, panel-based access to the long tail. [GUI][gui] · [Toolbox][toolbox] · [Ribbon source][widget]

Research snapshot: 2026-10-25. Stock behavior below uses the QGIS **3.44** manual/source; newer **testing** documentation is explicitly separated. Plugin implementation details come from its linked repository’s inspected `main` files unless a release-specific source is noted; this was source/document research, not an installed-plugin usability test.

## 1. Which ribbon plugin actually exists?

- **Name:** Ribbon Toolbar, plugin ID 4972, package `ribbon_toolbar`. Its description says “LibreOffice-like tabbed ribbon interface,” not a stock QGIS ribbon. [Registry][registry]
- **Maintainer:** registry account **eithanwes**; credited authors **Eithan Weiss Schonberg and Anita Graser**. [Registry][registry]
- **Latest listed release:** **0.5.0**, uploaded **2026-09-27 04:47:49 UTC** on the version page; approved but explicitly **Experimental**. Declared compatibility is QGIS **3.22.0–4.99.0**; that is metadata, not independently tested compatibility. [Release][release]
- **Source/home/issues:** [eithanwes/ribbon_toolbar][repo] and its [issue tracker](https://github.com/eithanwes/ribbon_toolbar/issues). The README warns: “entirely generated by AI as a proof of concept. Use with caution.” [README][repo]
- **Related repository:** [anitagraser/qgis-tabbed-ui][fork] is the related development experiment, not evidence of an independently listed second plugin. The 0.5.0 changelog explicitly says the redesign was ported from that repository; Graser directs users to the same Ribbon Toolbar 0.5 listing. [Release][release] · [Author’s explanation][experiment]
- **Maintenance assessment:** do **not** call it abandoned: the registry has a September 2026 release, and the author published a September 29 explanation. Equally, do not call it production-ready: Graser says “Consider this a click-dummy that should facilitate discussion.” [Release][release] · [Author’s explanation][experiment]
- **Search scope:** searches for “QGIS ribbon plugin,” “ribbon toolbar QGIS,” “QRibbon,” and “Ribbon UI QGIS plugin” identified the above registry listing and related fork. No additional independently listed QGIS ribbon plugin was verified; this is a bounded research result, not proof that no other project exists. [Registry][registry] · [Related fork][fork]
- **QRibbon naming trap:** the examined [hdijkema/QRibbon](https://github.com/hdijkema/QRibbon) describes itself simply as “A Ribbon Toolbar / Menu for Qt”; it is not the identified QGIS plugin. [QRibbon README](https://github.com/hdijkema/QRibbon)

## 2. Structure and customization

### Stock QGIS

- **Core structure:** standard menus include Project, Edit, View, Layer, Settings, Plugins, Vector, Raster, Database, Web, Mesh, Processing, and Help; platform placement can vary. These are menus, not ribbon tabs. [Menu reference][gui]
- **Groups:** task-specific toolbars include Project, Map Navigation, Attributes, Selection, Digitizing, Advanced Digitizing, Shape Digitizing, Snapping, Label, GPS, Raster, Vector, and Processing Algorithms. Panels handle more complex interactions. [Toolbars/panels][bars]
- **Contextual equivalent:** editing actions require edit mode and geometry-dependent tools activate according to the selected layer’s geometry. This is contextual enablement, not a documented contextual-ribbon-tab system. [Edit menu][edit]
- **Layout workspace:** Print Layout opens its own menus, toolbars, canvas, and panels; Item Properties changes with the selected layout item. This is a separate task workspace rather than a layout tab added to a ribbon. [Layout interface][layout]
- **Plugins:** third-party plugins can extend existing menus/toolbars or supply their own toolbar; the default plugin-menu destination is Plugins, with domain-menu alternatives. [GUI][bars] · [Plugin cookbook][plugins]
- **Project/backstage equivalent:** Project contains New/Open/Save, templates, recent projects, properties, export, print-layout creation, and layout management. It is a normal menu, not a full-window backstage page. [Project menu][project]
- **Quick access:** [INFERENCE] the Project and Map Navigation toolbars provide the always-visible-shortcut role often served by a ribbon quick-access toolbar; the documented stock interface does not identify a separate Office-style QAT. [GUI structure and toolbar list][gui]
- **Toolbar visibility and placement:** View > Toolbars / Panels, or right-clicking the menu bar/toolbar, shows and hides them; toolbars and panels can be moved around the interface. [Toolbars/panels][bars]
- **Interface Customization:** Settings > Interface Customization can hide menus/submenus, panels, status-bar elements, entire toolbars or individual toolbar icons, and dialog widgets. Enable customization first; the 3.44 manual says changes require restart. [Customization][custom]
- **Sharing/reset:** the customization can be saved/loaded as an **INI** file; disabling customization or launching `qgis --nocustomization` restores access. This is not a ribbon JSON/XML layout system. [Customization][custom]
- **Adding/reordering distinction:** the 3.44 customization section documents hiding/showing, not a general drag-and-drop command-reordering editor; toolbar placement is separately movable. Do not assume a full ribbon-style editor from those docs. [Customization][custom] · [Toolbar placement][bars]
- **Newer documented capability:** the **testing** manual additionally documents user-defined menus/toolbars, an action-search panel, and dragging actions into those custom containers. The requested `/4.2/` documentation URL redirected to testing during research, so this is not asserted as a shipped 3.44 feature or a verified release milestone. [Testing customization][custom-testing]
- **Command search:** Locator is in the status bar, activated with **Ctrl+K**; prefixes include `.` for actions, `a` for Processing algorithms, `pl` for project layouts, `set` for settings, and `ef` for in-place editing algorithms. Filters can be enabled, made default, and assigned prefixes; plugins can add filters. [Locator][locator] · [Locator settings][locator-settings]

### Ribbon Toolbar plugin

- **Tabs:** inspected source orders **Project, Home, View, Raster, Vector, Mesh, GPS, Styling, Plugins**, with **Home** initially selected. The release notes list the same categories, though not in this source order. [Tab configuration][tabs] · [Home][home] · [Release][release]
- **Groups:** Home explicitly groups **Layer, Identify, Pan, Zoom, Selection, Attributes**; Project groups **New, Open, Save, Project Settings, Layouts, Import/Export**. These are hand-arranged groups, not an automatic one-menu-item/one-button translation. [Home][home] · [Project definitions][rproject]
- **Domain assembly:** Vector merges Edit with Vector tools; other tab types derive groups from related native toolbars and then menu actions. [Vector definitions][vector] · [Tab schema][spec]
- **Core/contextual distinction:** [INFERENCE] these are principally static functional tabs, not selection-triggered contextual tabs: the builder walks a configured tab list; it omits missing menus and empty toolbar-based tabs rather than installing selection-driven tab-appearance rules. [Builder][widget] · [Tab schema][spec]
- **Plugins tab:** includes Plugin Manager, the native Plugins toolbar, and third-party plugin toolbars; plugin menus remain accessible through the hamburger menu rather than being expanded wholesale into ribbon buttons. [Plugins definitions][rplugins] · [Builder][widget]
- **Project/backstage:** Project is an ordinary ribbon tab containing project commands; the upper-right hamburger exposes the existing QGIS menu hierarchy. No backstage page is implemented by these components. [Project definitions][rproject] · [Integration code][integration]
- **Quick access bar:** upper-left controls are Toggle Menu Bar, Open Project, Save Project, Select Features, and Identify. Upper-right hamburger access is rebuilt when opened to include later-added menus. [Integration code][integration]
- **Customization:** README explicitly lists **“Customization of ribbons” as out of scope**; Graser confirms no customization UI in 0.5. [README][repo] · [Author’s explanation][experiment]
- **Configuration format:** layouts are Python tab modules and tables (`TAB_MODULES`, `GROUPS`, `BUTTON_MENUS`, `SHORT_LABELS`, `ICON_ONLY`, `TOOLBAR_GROUP_OPTIONS`), not a documented user-editable JSON/XML configuration. The schema supports action/menu object names, submenu references, menu expansion, and panel toggles. [Configuration implementation][tabs] · [Tab schema][spec]
- **Reordering/hiding:** [INFERENCE] changing tab/group order requires editing these source definitions; the inspected integration creates a non-movable, non-floatable ribbon toolbar rather than a user reorder editor. Switching back to classic UI is supported. [Configuration][tabs] · [Integration][integration] · [README][repo]
- **Command search:** the plugin does not introduce a replacement search in the inspected ribbon/integration code; [INFERENCE] retaining QGIS’s Locator is the intended low-cost command-search route, but this was not exercised in an installed session. [Builder][widget] · [Integration][integration] · [Stock Locator][locator]

## 3. Control types and default-action semantics

### Stock QGIS

| Control | Concrete use and evidence |
| --- | --- |
| Ordinary toolbar buttons | New/Open/Save in Project; Pan/Zoom in Map Navigation. These are not a documented big-primary/small-secondary ribbon hierarchy; icon size is configurable globally. [GUI][gui] · [General settings][general] |
| **Last-used split buttons** | Mouse selection groups rectangle, polygon, freehand, and radius selection; advanced selection groups form, expression, all, and invert. `MenuButtonPopup` gives separate main-action/arrow behavior; `toolButtonActionTriggered()` changes the default and stores the selection choice. [Official source, construction][stock-selection] · [Handler][stock-handler] |
| Other split-button families | Measure groups line, area, bearing, and angle; Vertex Tool groups all-layers/current-layer variants; Move groups move/copy-and-move. Source connects these to the default-changing handler. Do not assume all families persist choices perfectly: the inspected measure restore/store cases are not identical. [Official source][stock-controls] · [Handler][stock-handler] |
| **Fixed-default split button** | Create Annotation Layer has a main action fixed to creation, plus menu access to creation and main annotation-layer properties; it is not wired to the generic last-used handler there. [Official source][stock-annotation] |
| Menu-only dropdown | All Edits uses `InstantPopup`, distinct from the actionable main face of a split button. Map Themes in the Layers panel is also an `InstantPopup` menu. [Official source][stock-controls] · [Map-theme source][stock-themes] |
| Toggles | Toggle Editing controls edit mode; Show Map Tips is an Attributes-toolbar/menu command. [Edit and View tables][gui] |
| Combos/value controls | Status-bar scale controls and the layout zoom combo are direct value selectors, not command galleries. [Status bar][status] · [Layout interface][layout] |
| Visual galleries | Style Manager displays previewed symbols, color ramps, text formats and label settings; it offers icon/list views, thumbnail sizing, tags, favorites, and smart groups. These live in a style-management dialog, not the main toolbar. [Style Manager][styles] |

### Ribbon Toolbar plugin

- **Large vs small:** large buttons put text below icons; small buttons use text beside icons or icon-only display. Groups combine large buttons with configurable multirow small-button grids. README calls the former frequently used tools and the latter secondary tools; Graser says prominence was based on her subjective experience, not measured usage. [Buttons][buttons] · [Groups][groups] · [README][repo] · [Author’s explanation][experiment]
- **Fixed-default split implementation:** `setDefaultAction(action)` plus `MenuButtonPopup` implements `BUTTON_MENUS`; the inspected factory does not replace that default when an alternative is chosen. This is different from stock QGIS’s generic last-used handler. [Button factory][buttons] · [Configuration contract][tabs] · [Stock handler][stock-handler]
- **Project examples:** **New** creates a new project, arrow opens templates; **Open** opens a project, arrow opens recent projects; **Save** saves the project, arrow opens storage destinations. The menus reuse existing named QGIS menus. [Project definitions][rproject] · [Button factory][buttons]
- **Home examples:** **Select Features** retains its named default, arrow lists polygon/freehand/radius/all/reselect; **Deselect Active Layer** offers Deselect All; **Add Layer** runs Data Source Manager, arrow offers embed layers/groups and layer-definition import. [Release 0.5.0 Home definitions][home-release] · [Button factory][buttons]
- **Vector examples:** **Paste Features** has paste-as-new-vector/paste-as-scratch alternatives; **Enable Snapping** has a Snapping Options arrow entry. These are specific pairings, not menus of unrelated tools. [Vector definitions][vector]
- **Dropdown-only examples:** Home’s **Measure** is a popup of the existing Measure submenu, not the stock changing-default measurement split button; Project’s **DWG/DXF** is a constructed submenu. Menu-backed arranged entries use `InstantPopup`. [Home][home] · [Project][rproject] · [Buttons][buttons]
- **Inherited widgets:** native `QToolButton` widgets can be cloned, copying their popup mode/menu and forwarding clicks to the hidden source button; this is a separate path from the explicit fixed-default `BUTTON_MENUS` path. Do not generalize one default policy to every ribbon control. [Button cloning][buttons]
- **Toggles:** ordinary reused QActions preserve action state; panel entries use checkable show/hide actions with visibility synchronization. Examples include Toggle Editing and Show Overview. [Buttons][buttons] · [Action resolver][actions] · [Vector][vector] · [View][view]
- **Galleries/combos:** [INFERENCE] no dedicated ribbon gallery or combo implementation was found in the inspected factories. In fact, the widget-cloning path explicitly rejects non-`QToolButton` widgets such as spinboxes; styling previews remain a stock-dialog concern rather than a demonstrated inline ribbon gallery. [Buttons][buttons] · [Groups][groups] · [Style Manager][styles]
- **Terminology warning:** source `split_group` means a **group layout split into large and small buttons**, not necessarily a split button. Actual main-action-plus-arrow behavior is `MenuButtonPopup` in the button factory. [Groups][groups] · [Buttons][buttons]

## 4. Where niche features go

### Stock QGIS

- **Processing Toolbox:** algorithms are organized by provider, alongside models/scripts; search matches names or keywords, and Recently Used/Favorites provide repeat access without a dedicated top-level button for every algorithm. Batch execution is exposed through an algorithm’s context menu. [Toolbox][toolbox]
- **Context-sensitive narrowing:** Edit Features In-Place restricts the toolbox to algorithms suitable for the active layer; the Locator also has an `ef` filter. [Toolbox][toolbox] · [Locator settings][locator-settings]
- **Specialist panels:** GPS, temporal control, advanced digitizing, statistics, layer styling, and geometry validation have panel-based entry points; panel visibility is user-controlled. [Panel list][bars]
- **Selection-dependent settings:** layout Item Properties shows the selected item’s settings, avoiding a permanent global toolbar for every item property. [Layout interface][layout]
- **Not search-only:** documented algorithms are browsable in the Toolbox as well as searchable; do not describe Locator as the sole home of the long tail. [Toolbox][toolbox] · [Locator settings][locator-settings]

### Ribbon Toolbar plugin

- **“More” fallback:** hand-arranged tabs collect unplaced source-menu/related-toolbar actions into a More group on the first tab sharing that menu; explicit exclusions prevent selected duplicates from reappearing. [Builder][widget] · [Schema][spec]
- **Native menus remain available:** the hamburger retains the QGIS menu tree, including plugin menus deliberately omitted from the Plugins ribbon’s menu group. [Integration][integration] · [Plugins definitions][rplugins]
- **Toolbox access:** View and Vector each explicitly promote the Processing Toolbox launcher rather than placing every algorithm on the ribbon. [View][view] · [Vector][vector]
- **No demonstrated contextual-tab solution:** Mesh/GPS/Styling are configured functional categories, while existing QGIS actions supply much of the command state. [INFERENCE] this prototype does not establish an ArcGIS-style “only show a tab when a matching object is selected” pattern. [Configuration][tabs] · [Builder][widget] · [Actions][actions]
- **Plugin scaling limitation:** Graser documents that a newly installed plugin toolbar first appears separately, then is absorbed into Plugins after restart; she explicitly says this is “not sustainable” for users with many plugins. This is an acknowledged limitation, not a polished extensibility rule. [Author’s explanation][experiment]

## 5. Duplication: deliberate shortcuts versus accidental repetition

### Stock QGIS

- **Menu + toolbar duplication is normal:** the manual says most menu options have corresponding toolbar tools, but the two structures are not identical. New/Open/Save appear in Project menu and toolbar, for example. [Menu reference][gui]
- **Multiple entry points:** Style Manager opens from Settings, the Project toolbar, or symbol/text configuration in Layer Properties. Layout Manager is reachable from both the main Project workspace and the layout window. [Style Manager][styles] · [Layout Manager][layout]
- There are no stock ribbon tabs to compare; these are cross-surface/workspace duplicates, not evidence of repeated ribbon-tab buttons. [GUI structure][gui] · [Layout interface][layout]

### Ribbon Toolbar plugin

- **Explicit cross-tab duplication:** the same `SELECTION_GROUP` is defined in Home and reused by Vector, giving both tabs selection controls. [Home][home] · [Vector][vector]
- **Another example:** `toolboxAction` appears in Processing groups on both View and Vector. [View][view] · [Vector][vector]
- **QAT duplication:** Open/Save are on the quick-access bar and Project tab; Select/Identify are on quick access and Home. [Integration][integration] · [Project][rproject] · [Home][home]
- **Deduplication is selective:** the builder tracks native action identities to avoid repeating toolbar commands in a tab’s menu-derived groups; Home explicitly excludes variants already inside button menus and a duplicate Measure widget. It does not enforce global one-command/one-tab uniqueness. [Builder][widget] · [Home exclusions][home]
- **Shared command mapping:** named entries resolve to existing `QAction`/`QMenu` objects in the QGIS main window; `dock:` entries resolve panels, `/*` expands menus, and tuple entries construct menus from resolved actions. Ordinary buttons use the source QAction, so duplicated surfaces need not duplicate command implementations. [Resolver][actions] · [Configuration contract][tabs] · [Buttons][buttons]

## 6. Published rules for plugin authors and UI design

- **Default integration:** `iface.addPluginToMenu("&My Plugin", action)` adds under Plugins; the cookbook demonstrates adding the same QAction to the Plugins toolbar with `addToolBarIcon()` and removing both in `unload()`. [Plugin cookbook][plugins]
- **Domain placement:** the cookbook recommends predefined menu methods “to keep consistency in how plugin entries are organized,” naming Raster, Vector, Database, and Web alternatives. It permits a custom top-level menu but does not present that as the default. [Plugin cookbook][plugins]
- **Own toolbar is available:** `iface.addToolBar(name)` creates a named toolbar; `addToolBarIcon(action)` specifically adds to the **Plugins** toolbar. Domain-specific toolbar APIs also exist. This is API capability, not a guideline requiring one toolbar per plugin. [QgisInterface API][iface]
- **Prefer Processing where appropriate:** “it might be a better option to add its functionality as a Processing algorithm”; the cookbook cites integration with modeler/batch processing and describes registering an algorithm provider. [Processing-plugin cookbook][provider]
- **Avoid a settings-menu explosion:** the configuration manual explicitly encourages embedding plugin settings in the standard Options dialog instead of adding separate configuration dialogs/menu entries. [Configuration introduction][general]
- **HIG grouping:** “Group related elements using group boxes”; avoid one-item groups. This is a general GUI/dialog rule, not a ribbon-specific button-placement standard. [QGIS Developer HIG][hig]
- **HIG complexity:** “Separate advanced options from basic ones”; advanced features should be below a divider or on another tab. [HIG][hig]
- **HIG restraint:** “Strive to keep the user interface minimalistic and use sensible defaults.” [HIG][hig]
- **HIG safety and consistency:** keep harmful actions away from harmless ones, use consistent iconography, do not nest tabs, and append an ellipsis when a button opens another dialog. [HIG][hig]
- **Evidence boundary:** these sources do not supply a QGIS-wide ribbon-button quota, mandatory split-button policy, or formal per-plugin ribbon allocation rule; the experimental plugin’s Python layout tables are implementation choices, not official QGIS HIG. [HIG][hig] · [Plugin cookbook][plugins] · [Ribbon configuration][tabs]

## 7. Lessons for RustGIS

All recommendations below are **[INFERENCE]**, grounded in the linked observations rather than claims of QGIS policy.

- **Make the ribbon a promotion layer, not the complete command inventory.** Keep algorithms browsable/searchable in a toolbox and promote only a launcher plus a curated subset; QGIS’s Toolbox already combines provider groups, search, Favorites, and Recently Used. [Toolbox][toolbox] · [Ribbon View][view]
- **Choose fixed versus last-used defaults deliberately per family.** New/Open/Save with fixed alternatives are easy to explain; stock QGIS selection changes its main action, whereas the ribbon’s explicit Select Features mapping stays fixed. Document the distinction in the control model and tooltip. [Project][rproject] · [Buttons][buttons] · [Stock selection][stock-selection] · [Handler][stock-handler]
- **Do not call every arrow a split button.** Menu-only Measure/DWG-DXF launchers have no repeatable main action; separate these from actionable main faces such as Save plus destinations. [Home][home] · [Project][rproject] · [Buttons][buttons]
- **Prioritize using workflow evidence, then permit correction.** The QGIS prototype’s large-button choices are explicitly subjective and customization is absent; RustGIS should not mistake that experiment for measured evidence of frequency. [Author’s explanation][experiment] · [README][repo]
- **Permit useful duplication, but bind to one command identity.** Home/Vector selection and View/Vector Toolbox are concrete useful repeats; identity-based deduplication can still remove accidental menu/toolbar repetition. [Home][home] · [Vector][vector] · [View][view] · [Builder][widget]
- **Give extensions a constrained home and a Processing-provider path.** Do not let every extension demand a permanent tab/toolbar; the prototype author identifies plugin-toolbar absorption as unsustainable, while stock QGIS supports domain menus and Processing providers. [Author’s explanation][experiment] · [Plugin cookbook][plugins] · [Provider cookbook][provider]
- **Use galleries for visual choices and panels for property-heavy work.** QGIS previews styles in a dedicated manager and changes layout Item Properties with selection; these are stronger precedents than turning every property into a command button. [Style Manager][styles] · [Layout][layout]
- **Keep search independent of visible placement.** Locator’s action/algorithm/layout/settings filters are a useful complement to hidden toolbars and minimal interfaces; preserve command discoverability when users simplify the ribbon. [Locator][locator] · [Locator settings][locator-settings] · [Customization][custom]
- **Offer reversible simplification and shareable profiles/configuration.** QGIS’s INI customization and explicit reset path are useful precedents; do not copy the ribbon prototype’s absence of customization as a final design. [Customization][custom] · [README][repo]
- **Separate basics from specialist tools and destructive actions.** Apply the published HIG’s complexity and safety rules to ribbon groups, without pretending the HIG prescribes an Office layout. [HIG][hig]
